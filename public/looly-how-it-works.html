OVERVIEW

Looly is a stealth Windows desktop app that listens to job interviews in real time and streams instant AI-generated answers — completely invisible to Zoom, Teams, and Google Meet screen sharing. It combines a Tauri v2 + Rust desktop shell with a Node.js/Express backend on Railway to deliver a seamless, invisible co-pilot experience.

Microphone Input → Web Speech API → Express Backend → Groq LLaMA → SSE Stream → Tauri WebView

// 02

STEALTH ENGINE

The core differentiator: Looly is genuinely invisible to screen-sharing software at the Windows driver level.

👁 SetWindowDisplayAffinity

Looly calls the Win32 SetWindowDisplayAffinity API with WDA_EXCLUDEFROMCAPTURE. This instructs the Windows Display Driver Model (WDDM) to exclude the window from all screen capture operations — the window renders on the physical monitor but appears as a black rectangle in any capture stream, including Zoom, Teams, and OBS.

🪟 WS_EX_TOOLWINDOW

The extended window style WS_EX_TOOLWINDOW hides the app from the Windows taskbar and Alt+Tab switcher. This means the interviewer sees no suspicious window in the taskbar — Looly is effectively invisible at the OS UI level as well as the capture level.

// Rust side (src-tauri/src/main.rs)
fn set_stealth_mode(window: &Window) {
  let hwnd = window.hwnd().unwrap();
  // Hide from screen capture
  SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE);
  // Hide from taskbar & Alt+Tab
  let style = GetWindowLong(hwnd, GWL_EXSTYLE);
  SetWindowLong(hwnd, GWL_EXSTYLE, style | WS_EX_TOOLWINDOW);
}

REAL-TIME SPEECH RECOGNITION

Web Speech API + Silence Detection

The speech listener uses the browser-native SpeechRecognition API running inside the Tauri WebView. It captures interim results in real time, building up the transcript. A 4-second silence timer runs alongside — when no new words arrive for 4 seconds, the current transcript is automatically submitted to the AI pipeline.

Mic Stream → SpeechRecognition API → Interim Transcript → 4s Silence Timer → Auto Submit
// Silence-detection logic (React/TypeScript)
recognition.onresult = (event) => {
  const transcript = Array.from(event.results)
    .map(r => r[0].transcript).join('');
  setLiveText(transcript);
  clearTimeout(silenceTimer.current);
  silenceTimer.current = setTimeout(() => {
    submitQuestion(transcript); // 4s of silence
  }, 4000);
};

// 04

AI ANSWER PIPELINE (SSE STREAMING)

Answers stream token-by-token using Server-Sent Events for zero-latency perceived response.

Free Tier vs Pro Tier
FREE (BYOK)

User provides their own Groq API key. The key is stored in localStorage and sent with each request. 10-day trial period.

PRO (KEY POOL)

Requests route through a backend key rotation pool. No API key needed. Keys cycle automatically to avoid rate limits.

// Backend SSE route (Node.js/Express)
app.post('/api/ask', async (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  
  const apiKey = req.body.isPro
    ? getNextKeyFromPool() // rotate through pool
    : req.body.userKey; // user's own key
  
  const stream = await groq.chat.completions.create({
    model: 'llama-3.3-70b-versatile',
    messages: [{ role: 'user', content: question }],
    stream: true
  });
  
  for await (const chunk of stream) {
    const token = chunk.choices[0]?.delta?.content;
    if (token) res.write(`data: ${token}\n\n`);
  }
  res.write('data: [DONE]\n\n'); res.end();
});

SCREENSHOT ANALYSIS MODE

When the user presses the screenshot hotkey, a native Rust Tauri command captures the full screen using the Windows GDI API, encodes it to PNG bytes, and passes it to the React frontend. The frontend draws the image onto a canvas element and compresses it to a base64 JPEG at 60% quality — drastically reducing payload size before sending to the backend.

Hotkey Trigger → Rust GDI Capture → Canvas Compression → Base64 JPEG → LLaMA 4 Scout Vision → SSE Answer
// Rust Tauri command
#[tauri::command]
fn capture_screen() -> Result<Vec<u8>, String> {
  let screen = Screen::all().unwrap()[0];
  let image = screen.capture().unwrap();
  image.to_png(Compression::Fast).unwrap()
}

License Activation in Desktop App

The Tauri app validates the license key against Supabase using the Tauri HTTP plugin (not WebView2 fetch — which was silently blocked in production builds by Tauri's capability system). The plugin requires explicit URL scopes to be declared in the capabilities manifest, a subtle but critical configuration that blocked all network calls until discovered.

// tauri.conf.json — capability scope (critical fix)
{
  "permissions": [
    "http:default",
    { "identifier": "http:allow-fetch",
      "allow": [{ "url": "https://your-backend.railway.app/**" }] }
  ]
}

// 07

KEY ENGINEERING CHALLENGES

⚡ Tauri HTTP Plugin Scope Blocking
All HTTP requests from the desktop app were silently failing in production builds. Root cause: Tauri v2 requires every URL the app may fetch to be explicitly listed in the capabilities manifest. Without this, requests fail with no error — they simply never fire. Fixed by declaring the Railway backend domain in the capability scope.
⚡ Railway SMTP Port Blocking
Email delivery via Gmail SMTP on port 465 (SSL) failed silently on Railway. Railway blocks outbound IPv6 connections used by port 465. Fixed by switching to port 587 (STARTTLS) with explicit tls: { rejectUnauthorized: false } and requireTLS: true in the nodemailer config.
⚡ Payment Email Blocking the UI
The payment success handler was awaiting the email send operation, causing the UI to hang for 2-3 seconds before showing confirmation. Fixed by making email send fire-and-forget — the confirmation response returns immediately; email delivery happens asynchronously in the background.
⚡ Groq Rate Limits for Pro Users
A single Groq API key has per-minute token limits that Pro users could hit during an active interview. Fixed by building a key rotation pool on the backend — each request picks the next available key in round-robin order. Exhausted keys are automatically retired until their rate-limit window resets.

ARCHITECTURE SUMMARY

  • ▶ Desktop layer (Rust/Tauri v2): manages window stealth, system tray, native screen capture, and IPC bridge to the React WebView.
  • ▶ UI layer (React/TypeScript): handles speech recognition, question submission, token-by-token SSE rendering, and code block parsing.
  • ▶ Backend (Node.js/Express on Railway): serves the marketing site, proxies AI requests, manages Razorpay webhooks, rotates API keys, sends transactional email, and hosts the admin dashboard.
  • ▶ Data layer (Supabase/PostgreSQL): stores users, license keys, analytics events, download records, and admin metrics.
  • ▶ Auth (Supabase + Google OAuth2): users sign in on the marketing site to retrieve their license key; the admin dashboard is protected by a separate password gate.
